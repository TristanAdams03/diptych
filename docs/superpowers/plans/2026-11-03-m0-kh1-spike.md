# Milestone 0: KH1 Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove on the user's Windows PC, then on the AYN Thor through GameNative, that:
- a `dinput8.dll` proxy loads into `KINGDOM HEARTS FINAL MIX.exe` (Steam 1.0.0.2) without breaking controls;
- it serves a loopback WebSocket the Diptych app can reach;
- world, room and Sora's HP read correctly;
- one write mechanism for casting a shortcut can be found and works safely.

**Architecture:** An x64 proxy DLL forwards DirectInput to the real system `dinput8.dll`. Only inside KH1, and only on a recognised build, it starts:
- a loopback WebSocket server, reusing the TTW plugin's portable WebSocket core, Winsock server and JSON envelope;
- a 10 Hz reader thread doing guarded reads at module-relative offsets.

Commands go to a queue drained by the reader thread. A spike Diptych app (adapted from the TTW spike app) shows the values. A PowerShell probe client lets Claude, running in WSL, read live values while the user plays on the PC.

**Tech Stack:** C++20, CMake ≥3.25, MSVC x64 `/MT`, nlohmann/json 3.11.3, doctest 2.4.11 (pins and hashes as in `ttw-dualscreen/plugin/CMakeLists.txt`) · Kotlin/Compose app (same stack and Docker image as `ttw-dualscreen/app`) · Python 3.12 + `websockets` 13.1 mock · PowerShell 5.1 probe client.

## Global Constraints
- KH1 mod port **7970**, bound to **127.0.0.1 only**. Never 7786–7788, 8765, 27000, 28000 or 7960.
- Addresses are **offsets from `GetModuleHandleW(nullptr)`**. LuaBackend's default KH1 base is 0.
- **Version gate:**
  - the byte at offset `0x4698D2` == `0x6A` ⇒ `steam-1.0.0.2` (supported);
  - the byte at `0x46A822` == `0x6A` ⇒ `egs-1.0.0.10` (recognised, `supported:false` in M0);
  - anything else ⇒ `unknown` (`supported:false`).
- Source: `gaithern/KH1-LUA-LIBRARY` `VersionCheck.lua`.
- **Only active in `KINGDOM HEARTS FINAL MIX.exe`** (case-insensitive basename). In any other process (the 1.5+2.5 launcher, KH2, BBS, ReCoM) the DLL is a pure passthrough and starts nothing.
- **No disk writes except the optional log** `diptych_kh1.log` beside the DLL, when that folder is writable. Never patch game code on disk.
- In M0, **writes to game memory happen only through the `kh1.pressInput` experiment**, and only in a safe state: not in a menu, cutscene or Gummi, and with a supported build.
- Every game read goes through an SEH guard. A fault yields `null` and disables that reader for the session.
- Nothing blocks or waits inside `DllMain`. The server and reader start on a thread created there, which never waits on the loader lock.
- Protocol envelope is identical to TTW v0 (`hello`/`welcome`/`subscribe`/`state`/`command`/`result`/`ping`/`pong`/`error`). `welcome` adds `gameId:"kh1"`, `gameBuild`, `supported`.

## Review Focus
1. **The DLL loads into the 1.5+2.5 launcher and the other collection games:** pure passthrough, no thread and no socket. Covered by Task 3's `process_gate` tests.
2. **The real system `dinput8.dll` can't be loaded:** the exported `DirectInput8Create` returns `DIERR_NOTINITIALIZED` (`0x80070015`) and logs the reason, rather than crashing. Covered by Task 3's `forwarder_missing_target` test.
3. **Unrecognised build** (a Steam update ships): `welcome.supported:false`, every state field `null`, every command `error:"unsupported build"`. Covered by Task 4's `unsupported_build_blocks_all` test.
4. **`kh1.probe` asks for an offset outside the module image, or more than 256 bytes:** rejected with `error:"out of range"`. Covered by Task 4's `probe_bounds` test.
5. **`kh1.pressInput` while in a menu, cutscene or Gummi:** refused with `error:"not safe now"`, and nothing is written. Covered by Task 4's `press_refused_when_unsafe` test.

### Task 4: Spike reader thread and commands

**Files:**

**Interfaces:**
- Consumes: Task 2 (`WsServer`, `Info`, envelope) and Task 3 (`classify_build`, `LogRing`).
- Produces:
  - `struct IMemory { virtual std::optional<uint8_t> u8(uintptr_t off)=0; virtual std::optional<uint32_t> u32(uintptr_t off)=0; virtual std::optional<std::vector<uint8_t>> bytes(uintptr_t off, size_t n)=0; virtual bool write_u8(uintptr_t off, uint8_t v)=0; virtual size_t image_size()=0; };`
  - `nlohmann::json kh1_spike_state(IMemory&, int64_t seq, int64_t ms, bool supported)`: fields per Task 1. When `!supported`, every game field is `null`.
  - `bool safe_now(IMemory&)`: true only when the menu, cutscene and Gummi reads are all readable and all clear.
  - `std::string run_kh1_command(IMemory&, bool supported, const std::string& id, const std::string& name, const nlohmann::json& args, PressScheduler&)`
  - `class PressScheduler { void start(int byteIndex, uint8_t mask, int durationMs); void tick(IMemory&, int64_t nowMs); }`: while active, ORs `mask` into the byte at `0x23407B4 + byteIndex` on every tick.
- The runtime loop:
  - ticks the press scheduler at **1 kHz**;
  - builds state at the subscribed rate (≤10 Hz);
  - drains up to 8 commands per 100 ms.
- Runtime start: compute `classify_build` → `Info{plugin:"0.0.1-spike", gameId:"kh1", gameBuild, supported: build==Steam1002}` → `WsServer.start("127.0.0.1", 7970, info)`. Log every step to the `LogRing` and to `diptych_kh1.log` if possible.
- A `kh1.log` command returns `{lines:[…last 200]}`. This is how the Thor run gets its log out.

## After the spike
The PC session results decide M1/M2:
- which world offset is right;
- the confirmed field widths;
- the input bit layout;
- whether `pressInput` can cast shortcuts, or whether a frame hook or game-function call is needed.

The Thor results decide whether the GameNative import and auto-override work as researched. If the proxy fails to load or breaks controls on either platform, stop and re-plan with the user.
