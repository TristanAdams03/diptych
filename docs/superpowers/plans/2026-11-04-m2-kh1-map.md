# KH1 Read-Only Map (late worlds) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The bottom screen shows the KH1 map tab for Neverland, Hollow Bastion and End of the World: the current room lit on a room diagram, chests opened / total per room, and live party HP/MP pinned beside it, in the approved style.

**Architecture:** The mod stays game-agnostic about map data. It gains one read-only command, `kh1.watch`, which tells it which memory regions to include, as hex, in each state frame. All KH1 knowledge (rooms, layouts, chest flags, party addresses) lives in JSON data files shipped in the app. The app picks which regions to watch for the current world, decodes them and draws the screen. Correcting an address then needs a data change, not a DLL.

**Tech Stack:** C++20 mod (existing `mods/kh1`, doctest, MSVC + Linux CI); Python 3 data generator and validator (`tools/data`); Kotlin + Compose app (existing `app/`, kotlinx.serialization, JUnit, Paparazzi screenshots).

**Spec:** `docs/superpowers/specs/2026-11-03-diptych-design.md` (§7, §7.1, §10, "Milestone order change"). Approved style: `docs/superpowers/specs/mockups/kh1-style/`. Research: `docs/research/kh1-late-worlds.md`, `docs/research/kh1-data-draft/*.json`. Spike results: `docs/spike/RESULTS.md`.

## Global Constraints

- Supported build: Steam 1.0.0.2 only. Every other build stays read-nothing and reports `unsupported build`, as today.
- Port 7970, loopback only. Existing protocol messages stay compatible; `kh1.spike` frames keep every field they have.
- M2 adds no game-memory writes. `kh1.watch` is read-only: every read is SEH-guarded, and only inside the main module image.
- Watch limits: at most 8 regions, each 1..256 bytes, 1024 bytes in total. The state rate stays ≤ 10 Hz.
- Style tokens: night-sky ground `#0b1433`; panel `#15235a` with a 2 dp `#9fc0ff` rim, radius 14 dp; gold `#ffd166` (chests); "you" fill `#3f8cff` with a white rim; muted text `#a9b9e6`; HP `#4fe08a` (≤40% `#ffb84f`); MP `#5aa8ff`. Fonts are Fredoka (headings, tabs) and Nunito (body), both OFL and bundled. Touch targets are ≥ 44 dp.
- No Square Enix assets. Room, chest and item names are text facts. Every data file has a `sources` list and keeps the research's citations. The AGPL Critical Mix script is cited, never copied.
- Each value in a data file carries `confidence`: `live` (checked on the user's PC), `source` or `derived`/`guess`. The app treats them all the same; the field is for people.
- Commits: author `ghost <t.j.adams06@gmail.com>`. Messages end with a blank line, then:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  `Claude-Session: https://claude.ai/code/session_019oN1T9KYsPh716Ayphvqnu`

## Review Focus

1. **A world or room id the data doesn't know** (other worlds, unnamed Neverland rooms 10–11, menus at world 255). Expected: the map area says "No map for this world yet" or shows "Room N", and party HP still shows. It never crashes or goes blank. Owner: Task 4 (`MapModel` tests) and Task 5 (screenshot).
2. **Regions that fail to read.** Expected: when a region's `hex` is null, its chests show "?" not "0", and party bars show "--". Owner: Task 3 (decoder tests).
3. **A world change mid-session.** Expected: the app re-sends `kh1.watch` for the new world within one frame of seeing the new world id, and the old world's chest counts never show under the new world. Owner: Task 4 (`Kh1Session` test).
4. **A reconnect after the game restarts.** Expected: the watch is re-sent after every `welcome`, because the mod forgets watches per connection. Owner: Task 4.
5. **End of the World's 39 rooms on a 540 dp-tall screen.** Expected: the map pans by drag, and centers on the current room on world entry. Text never goes below 11 sp. Owner: Task 5.

**Files:**

- Test: `mods/kh1/tests/test_kh1_watch.cpp`, additions to `mods/kh1/tests/test_runtime_win.cpp`

**Interfaces:**
- Produces, for the protocol:
  - **Command:** `kh1.watch` with `args:{regions:[{offset:int, length:int}]}`. Ok → `data:{count:int}`. An empty list clears the watch.
  - **Errors:** `out of range` for more than 8 regions, a length outside 1..256, a total over 1024, or a region outside the module image. `bad command` for a missing or ill-typed field. `unsupported build` on an unsupported build.
  - **State:** when a watch is set, `kh1.spike` state `data` gains `regions:[{offset:int, hex:string|null}]`, in watch order. `hex` is null when that read faults. With no watch set, the key is absent.
  - **Welcome:** `features` = `["spike","watch"]`, `plugin` = `"0.1.0"`.
- Produces, in C++:
  - `core::WatchSet parse_watch(const nlohmann::json& args, size_t imageSize)`, which throws `Fail{"out of range"}` / `Fail{"bad command"}`;
  - `nlohmann::json read_watch(IMemory&, const WatchSet&)`, which returns the `regions` array.
- The watch belongs to the client that set it. The runtime keeps one `WatchSet` per connection id and attaches it to that client's frames only. A client that disconnects drops its watch.

### Task 3: KH1 data files and generator

**Files:**
- Create: `tools/data/build_kh1_data.py`, `tools/data/layouts/kh1_layouts.json`, `tools/data/test_build_kh1_data.py`
- Create (generated, committed): `app/app/src/main/assets/kh1/worlds.json`, `app/app/src/main/assets/kh1/party.json`
- Create: `app/app/src/main/assets/kh1/SOURCES.md` (licenses and citations, from the research)

**Interfaces:**
- Produces `assets/kh1/worlds.json`:

```json
{"version":1,"sources":["..."],
 "worlds":[{"id":15,"name":"Hollow Bastion",
   "rooms":[{"id":0,"name":"Rising Falls","col":0,"row":0,"confidence":"source"}],
   "edges":[[0,1]],
   "chests":[{"name":"Hollow Bastion Rising Falls Water's Surface Chest","room":0,
              "offset":48143012,"bit":1,"contents":"Mythril Shard","confidence":"derived"}],
   "watch":[{"offset":48142992,"length":120}]}]}
```

  - `offset` is a decimal module offset, the same unit as the protocol.
  - `watch` lists the chest regions this world needs. They are computed: the smallest set of ≤256-byte spans covering every chest byte of the world.
  - A chest with several `room_ids` in the draft goes in its first room, and its name keeps the full description.
- Produces `assets/kh1/party.json`, taken from Task 1's results:
  `{"version":1,"battleBlock":{"offset":…,"stride":…,"members":3,"fields":{"hp":{"at":0,"width":4},"maxHp":…,"mp":…,"maxMp":…}},"slots":{"offset":…,"length":…},"names":{"0":"Sora","1":"Donald","2":"Goofy","8":"Peter Pan","9":"Beast",…}}`.
- Layouts (`tools/data/layouts/kh1_layouts.json`) are hand-authored by the implementer:
  - a `(col,row)` grid cell per room id, for the three worlds;
  - adjacency from `rooms.json` `adjacency`, with unknown links left out rather than invented;
  - rooms with the same name (Ship: Hold ×4, Final Dimension ×12) are separate cells with their ids in the label, e.g. "Ship: Hold (2)".

  - every chest byte lies inside one of its world's `watch` spans;
  - each `watch` span is ≤256 and a world's total is ≤1024;
  - the counts are Neverland 12 chests, Hollow Bastion 39, End of the World 26.

### Task 4: App — KH1 model, decoder and session

**Files:**

- Test: `app/app/src/test/java/com/diptych/app/kh1/DecodeTest.kt`, `MapModelTest.kt`, `Kh1SessionTest.kt`

**Interfaces:**
- `data class PartyMember(val name: String, val hp: Int?, val maxHp: Int?, val mp: Int?, val maxMp: Int?)`
- `fun decodeParty(party: PartyConfig, regions: List<RegionHex>): List<PartyMember>`. The names come from the slot bytes. An unknown char id gives "Guest". Null hex gives null fields.
- `fun chestOpened(chest: Chest, regions: List<RegionHex>): Boolean?`. It is null when the byte isn't covered or its region's hex is null.
- `data class RoomView(val id: Int, val label: String, val col: Int, val row: Int, val opened: Int?, val total: Int, val here: Boolean)`
- `data class MapView(val worldName: String, val roomName: String, val rooms: List<RoomView>, val edges: List<Pair<Int,Int>>, val chestsOpened: Int?, val chestsTotal: Int, val party: List<PartyMember>)`, where `rooms` is empty for a world with no data.
- `fun buildMapView(data: Kh1Data, state: SpikeData): MapView`:
  - an unknown world gives `worldName` "World N" and empty `rooms`;
  - an unknown room gives `roomName` "Room N";
  - `opened` is null if any of that room's chests is null.
- `class Kh1Session(client: SpikeClient, data: Kh1Data)`:
  - `val view: StateFlow<MapView?>`;
  - it sends `kh1.watch` with the party regions + the current world's `watch` after each `welcome` (when `supported` and `"watch"` in features), and again whenever `state.world` changes;
  - it ignores `regions` whose offsets don't match the latest watch it sent.
